# Activación posterior de Base P/Pinol Blanco

Este procedimiento se reserva para la ventana operativa autorizada. La migración 016 prepara el esquema. El comando de habilitación registra el corte y publica la presentación en el catálogo de Nexo Web.

1. Pausar las capturas en Compras, Elaboraciones, Ventas e Inventarios. Verificar el destino `calcquim_operational`, esquema `calcquim_operational`, y la secuencia de migraciones hasta la versión 015. Generar el respaldo con `server/scripts/backup-operational.mjs` y comprobar su restauración aislada con el procedimiento de recuperación existente.
2. Aplicar únicamente la migración 016 con el ejecutor `migrate` de `server/src/db/migrate.mjs` en la conexión operativa identificada, dentro de la ventana. Comparar el agregado comercial, los movimientos y el historial antes y después. La tabla `supply_inventory` debe quedar vacía. El script histórico `apply-inventory-operational.mjs` está acotado a la versión 006.
3. Publicar juntos el servidor y la compilación web. Confirmar que la API y la interfaz siguen funcionando con la tabla vacía. Revisar que el insumo autorizado conserva la botella de 1 litro, el vínculo con el producto 44 y el rendimiento de 1 a 20. Revalidar físicamente las 0 botellas cerradas al momento del corte. Si ese conteo cambió, detener el corte y actualizar el procedimiento.
4. Con la ventana todavía cerrada, ejecutar `enablePinolBlancoInventory` con `{confirmed:true,reason:"motivo y evidencia del conteo de corte"}` mediante el endpoint habitual de comandos, usando la revisión, generación y clave de idempotencia requeridas. Esta habilitación registra 0 botellas y agrega al catálogo la presentación de $130 MXN. Consultar `GET /api/v1/inventory` y comprobar el catálogo sin registrar una venta de prueba. Verificar que Verde conserve su configuración.
5. Verificar el saldo de 0 botellas y reanudar las capturas. Compras, Ventas y Elaboraciones deben usar cantidades enteras de botellas de 1 litro.

Las compras anteriores forman parte del historial y no se reaplican. Las compras nuevas registran el número de botellas recibidas. Cuando cambie la cantidad comprada, conciliar el destino físico y anular el renglón mediante el flujo de anulación de compra antes de recapturar. Las devoluciones requieren confirmar la cantidad de botellas originales cerradas.

Si el corte falla antes de habilitar el insumo, mantener la tabla vacía y usar la versión web anterior según el plan de recuperación. Si ya existen movimientos del insumo, cerrar las capturas y conciliar desde un respaldo verificado. Una restauración posterior al corte requiere conservar y revisar las operaciones posteriores.
